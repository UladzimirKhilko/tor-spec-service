# Короткие спецификации теплообменников БСИ

Статический веб-сервис (без сервера): загружаете отчёт "Спецификация" из
программы BelTO/ТеплоХИТ (PDF или скриншот), сервис переносит данные в
фирменный лист-шаблон компании (.vsdx) с автоматической конвертацией единиц
измерения там, где они не совпадают, и отдаёт готовый **.vsdx** и/или **PDF**.
Данные, которых нет в исходной спецификации (заказчик, цена, номер расчёта
и т.п.), всегда запрашиваются вручную в форме.

Вся обработка (чтение PDF, OCR картинок, сборка .vsdx, PDF) происходит
**в браузере пользователя** — сервер не нужен, поэтому подходит GitHub Pages.

## Быстрый старт (локально, для проверки)

Открыть `index.html` напрямую в браузере в целом сработает, но некоторые
браузеры блокируют `fetch()` локальных файлов (нужен для загрузки шаблона
.vsdx). Проще поднять локальный статический сервер:

```
cd tor-spec-service
python3 -m http.server 8080
```

Открыть http://localhost:8080

## Деплой на GitHub Pages

1. Создайте новый репозиторий на GitHub (публичный или приватный — Pages
   работает с обоими на платных планах; для бесплатного личного аккаунта
   Pages из приватного репозитория тоже доступен).
2. Загрузите в него все файлы из этой папки **как есть**, сохранив структуру:
   ```
   index.html
   css/style.css
   js/*.js
   templates/TOR-15M_13-1x.vsdx
   assets/*.png
   apps-script/Code.gs
   ```
3. Settings → Pages → Source: "Deploy from a branch" → выберите branch
   (обычно `main`) и папку `/root`.
4. Через 1–2 минуты сайт будет доступен по адресу вида
   `https://<ваш-логин>.github.io/<название-репозитория>/`.

## Журнал расчётов (Google Таблица)

Так как GitHub Pages не хранит данные сам, журнал ведётся в Google Таблице
через бесплатный Google Apps Script — веб-приложение, которое умеет
принимать запросы от статического сайта и дописывать строки в таблицу.

1. Создайте новую Google Таблицу (sheets.google.com), назовите как удобно.
2. В таблице: **Расширения → Apps Script**.
3. Удалите содержимое `Code.gs` и вставьте код из файла
   `apps-script/Code.gs` этого проекта. Сохраните (значок дискеты).
4. Нажмите **Деплой → Новый деплой**:
   - Тип: **Веб-приложение**
   - Описание: любое
   - Выполнять от имени: **Я (ваш аккаунт)**
   - У кого есть доступ: **Все**
5. Нажмите «Деплой», разрешите доступ (Google спросит подтверждение —
   это ваш собственный скрипт, работающий от вашего имени).
6. Скопируйте появившийся **URL веб-приложения** (заканчивается на `/exec`).
7. Откройте `js/config.js` в репозитории и вставьте ссылку:
   ```js
   const APPS_SCRIPT_URL = 'https://script.google.com/macros/s/XXXXXXXX/exec';
   ```
8. Сохраните и залейте изменение в GitHub — журнал заработает.

Каждая генерация .vsdx или PDF добавляет строку в лист "Журнал": дата,
шаблон, формат, марка, заказчик, место установки, номер расчёта, цена.

Если строка `APPS_SCRIPT_URL` оставлена пустой — сервис работает как
обычно, просто ничего никуда не логирует.

## Добавление новых шаблонов (моделей теплообменников)

Сейчас в пилоте один шаблон — `ТОР-15М/13-1х`. Чтобы добавить следующий:

1. Положите файл `.vsdx` нужной модели в `templates/`.
2. Определите ID нужных фигур (полей) внутри него — самый надёжный способ:
   переименовать `.vsdx` в `.zip`, распаковать, открыть
   `visio/pages/page1.xml` и найти `<Shape ID="...">...<Text>...` рядом с
   нужными подписями (либо попросите меня разобрать структуру нового файла
   так же, как я это сделал для ТОР-15М/13-1х).
3. Добавьте новый объект в массив `TEMPLATES` в `js/fieldMap.js` по
   аналогии с существующим — с ID нужных фигур, единицами измерения и
   тем, откуда брать значение (`sourceKeys` — ключи из `beltoParser.js`).
4. При необходимости добавьте новую печатную HTML-разметку в `index.html`
   (`#printSheet`) для PDF-варианта этой модели, аналогично существующей.

## Единицы измерения и конвертация

Список конвертаций — в `js/units.js`. Сейчас реализовано:
- кПа → кгс/см² (потери давления: BelTO обычно выдаёт кПа, шаблон — кгс/см²)
- Гкал/ч ↔ кВт (на случай, если источник в кВт)
- бар → кгс/см²

Если встретится другое несовпадение единиц — добавьте функцию в
`UNIT_CONVERTERS` (units.js) и укажите её имя в поле `convert` нужного
поля в `fieldMap.js`.

## Известные ограничения пилота

- Распознавание (парсер `beltoParser.js`) настроено под формат отчёта
  "Спецификация" BelTO — если формат исходника у поставщика/версии
  программы отличается, часть полей может не распознаться. Все
  автополя всё равно показываются пользователю для проверки и правки
  перед генерацией — это осознанное решение, а не баг.
- OCR (сканы/фото) заметно менее точен, чем разбор текстового PDF —
  всегда проверяйте значения после OCR.
- Поля `L, мм` (габаритный размер по патрубкам) в спецификации BelTO
  обычно отсутствуют — оставлено как поле ручного ввода.
- В шаблоне обнаружены две наложенные друг на друга ячейки для поля
  "Расход, нагреваемый контур" (ID 747 и 350) — значение записывается в
  обе одновременно, чтобы не промахнуться; при желании можно сузить
  после визуальной проверки в Visio.
